# 文章首页 Feed V1：从内容列表到可验证的学习入口

## 目标与范围

首期以大学生个人学习为主：用户打开文章首页，应能尽快看到**能读、想读、读完有收获**的英文内容。当前内容和行为数据还不够稠密，因此先采用可解释的轻量排序，而不是依赖协同过滤矩阵或把所有文章交给大模型排序。教师、管理员访问同一列表时仍可使用“发现”及分类；个性化信号不存在时自动回退到精选和新内容。

本版已落地首页“为你 / 发现 / 分类 / 视频”、继续阅读、知识点回顾、英语世界站外原文入口，以及真实曝光和阅读完成口径的初步看板。站外内容是**单独标识的跳转卡片**，不混成站内文章，也不会自动抓取全文或把学生画像发送给站外网站。

## 本次实现

| 环节 | 当前规则 |
| --- | --- |
| 候选资格 | 仅未删除的系统内容，或公开且已审核的用户上传内容；新 Feed 和旧协同过滤推荐的物化出口均执行此边界。文章详情仍按原有权限校验。 |
| 轻量取数 | 首页候选只取标题、标签、分类、难度、封面、约 320 字正文预览及长度，不传整篇正文；“发现”和分类由服务端分页。 |
| “为你”排序 | 兴趣、多个有效学习目标、专业、当前学期课表匹配；另考虑精选优先级、近 30 天新鲜度、已读 / 已完成降权及少量稳定扰动。前 8 篇限制单一分类最多 2 篇。 |
| 冷启动 | 没有画像也可按精选与新鲜度浏览；首页提示与小芽交流兴趣和学习目标。目标可以并存，不强制二选一。 |
| 学习动作 | 顶部提供未完成文章的“继续阅读”、小芽未读知识点消息对应文章的“知识点回顾”；没有时不显示。 |
| 站外探索 | 对学生复用已有开放内容候选池及画像匹配服务，仅展示最多 2 条 HTTPS 英文原文，明确标注“离开本平台”。搜索服务扩源仍属后续待评估，不在本次实现。 |
| 反馈 | 首屏和后续卡片真正进入滚动视窗至少 50% 才记 `IMPRESSION`；点击、明确“不感兴趣”分别记 `CLICK` / `DISMISS`，后者 90 天内从“为你”候选排除。下拉刷新带新种子并避开上次首屏部分内容。 |
| 学习指标 | 管理员看近 30 天去重的曝光用户-文章对、点击用户-文章对、点击后 7 天内真实阅读完成对及点击后完读率。点击本身不算完读。 |

课表只使用本地数据，按学年起始年份和秋 / 春学期过滤历史课程；学期划分暂按 8 月至次年 1 月为秋学期，其余月份为春学期。此规则依赖学校课表学年字段，须用真实数据再核验。学期信息不完整时宁可不用该信号，也不声称“今天有这门课”。

## 页面与接口

- `GET /api/feed/articles?mode=FOR_YOU|EXPLORE&category=technology&page=1&size=12&seed=...&exclude=1,2`：返回 `items`、`hasMore`、`nextPage`、`seed`，第一页另有 `continueReading`、`review`、`onboardingSuggested`。同一分页会话沿用 `seed`；“为你”单次排序的候选上限为精选 80 + 最新 220 篇，尚不是无限历史库分页。
- `POST /api/feed/events`：接收 `textId`、`eventType`（`IMPRESSION` / `CLICK` / `DISMISS`）、`source` 和零起始 `position`。服务端重新校验文章可见性；不接受由客户端声称的学习完成。
- `GET /api/admin/metrics/feed-learning?days=30`：仅管理员 / 运营可读，范围限制在 1–90 天。按用户-文章去重的点击后完读以 `text_learning_records.is_completed=1` 且完成时间在点击后 7 天内为准。
- 学生首页站外卡片仍调用既有 `GET /api/student/agent/content-recommendations`，不新增外部搜索服务。

底层沿用现有 `recommendation_events`（V13）、`text_learning_records`（V1）和文章知识点消息表（V56）；**本次不新增、不修改 Flyway 迁移**。旧 `/api/public/texts/recommended` 接口保留供兼容，但文章首页不再使用它；旧 `/api/public/texts/search` 仅在用户主动搜索时使用，仍返回旧版完整文章对象，后续应在保持阅读时长等字段准确的前提下改成摘要投影。

## 效果判断和隐私边界

首期看板只说明“从 Feed 进入并完成阅读”的关联，不代表因果效果，也不说明学生掌握了知识点。完读率分母是点击用户-文章对，分子是点击后 7 天内确实完成阅读的对；曝光只在可观察到卡片进入视野时记录。滚动浏览不是阅读完成，停留时间也不直接视为掌握。少量浏览器禁用 `IntersectionObserver` 时会缺失曝光，但点击仍可记录。

排序仅使用本平台已存的兴趣、目标、学习行为及学校主数据；不给教师开放单个学生的私人对话，也不把其画像发给第三方内容网站。站外点击由学生主动触发，浏览器直接打开 HTTPS 原文；第三方自身的追踪和版权边界仍需在正式扩源前评估。

## 下一阶段（未实现）

1. **内容供给与质量**：建立审核、去重、来源可信度、失效链接和版权检查；若要接入搜索服务，先做小范围白名单试验，再决定是否采用。把英文原文转写成适合学生水平的版本，需要沿用文章版本及来源溯源机制。
2. **个性化深度**：根据四 / 六级、考研、学术阅读等多目标和真实读写水平调难度；接入作文、错题、文章知识点回顾结果，把“薄弱点 → 推荐 → 练习 → 再测”闭环接起来。当前只做轻量主题匹配，不能宣称已经完成水平适配。
3. **真正的学习效果实验**：先监控漏斗（曝光 → 点击 → 完读 → 知识点回顾 / 题目正确率 → 7 日回访）与内容覆盖，再做新旧 Feed 的分组对照；重点比较有无学习提升和持续阅读，而非单纯 CTR。注意新用户、不同目标和难度的分层。
4. **性能与治理**：数据量增长后改为索引友好的游标 / 预计算候选，增加曝光事件去重与限流，统一站外点击的可审计事件，并完善画像与历史行为的保留 / 删除策略。

## 验收检查

1. 新学生默认进入“为你”，无兴趣和课表时也有可读内容；明确排除私有 / 未审核 UGC。
2. “发现”和分类可继续加载服务端下一页；刷新后首屏有轮换，同一分页会话顺序稳定。
3. 继续阅读与知识点回顾可打开原文章；站外卡片明确标识且仅点击时跳转。
4. 曝光只在卡片真实可见时写入，点击和“不感兴趣”可区分；管理员看到的完读不由点击代替。
5. 自动化测试覆盖冷启动匹配、课表学期、可见性、分页、事件校验和前端交互；上线前还需在带真实 Flyway 数据库的测试环境做一次端到端核验。
