# 小芽：阅读后知识点

学生完成一篇文章后，小芽按该学生的英语层级提取 1–3 个有原文依据的词汇、语法或句型知识点。阅读提交不等待提取完成；文章完成卡片会轮询结果，生成后也作为该学生的个人未读消息出现在小芽入口。管理员公告通知与个人消息分库存储，互不混用。

## 成绩与层级

当前本地数据（2026-09-19，只读核验）：`level_exam_scores` 共 293,513 条、79,196 位学生；考试名称为 CET4 的 219,467 条（77,968 位学生），CET6 的 73,104 条（28,011 位学生）。这两类记录的 `exam_type` 均为 `CET`，不能据此区分级别；`passing_score` 均为空，现有导入逻辑以 60 分推导 `is_passed`，该字段也不用于本功能的层级判断。平台账号与这些成绩记录匹配的学号共有 21,516 个。

本功能识别考试名称中的 CET4/CET6 或“英语四级/六级”，以 425 分作为产品的进阶线：六级达线 → 考研，四级达线或已有六级记录 → 六级，其余已有四级记录 → 四级。425 分是学习路径选择规则，不宣称 CET 官方设置统一及格线。没有成绩时回退到小芽学习档案中的自评水平，若也没有则从四级开始。该规则只读取分数，不修改历史数据。

## 生成与复用

当前版本仅在本地执行：读取文章实际完成的版本，抽取文本中的单词，与平台 ECDICT 的 CET4/CET6/考研标签及中文释义匹配；另使用明确可核对的句型规则。知识点附原句，不编造文章中不存在的例句，也不发送文章或学生成绩到外部 AI 服务。局限是讲解较为模板化；HiAgent 模型增强列入下方后续计划，目前尚未接入。

`article_learning_insights` 以 `text_id + content_version + target_level + SHA-256(正文)` 唯一缓存，文章或版本更新时才重新提取。`article_insight_messages` 以 `user_id + insight_id` 唯一投递，保存独立已读状态；同一缓存可供不同学生复用，但消息仅属于本人。数据库结构在 `V56__article_learning_insights.sql`，由 Flyway 在下一次后端部署时执行。当前运行库尚在 V54，未手动执行 DDL。

接口：`GET /api/student/agent/article-insights/{textId}`（必须已完成阅读）、`GET /api/student/agent/article-insights/unread`、`POST /api/student/agent/article-insights/messages/{id}/read`。以上接口仅允许学生/普通用户访问，查询和已读操作均按当前登录用户限定。

## 后续计划：HiAgent 专用知识点智能体

已获得项目方授权：可将文章正文发送至 HiAgent，用于生成阅读后知识点。下一阶段应在 HiAgent 创建一个**专用的“阅读后知识点”智能体**，与现有转写、出题、对话智能体分开配置；本次仅记录计划，没有创建远端智能体、配置密钥或发送正文。

1. 在 HiAgent 创建专用智能体并确定其应用 ID、密钥、调用地址、输出格式、超时和配额。凭据放在现有服务端的安全配置渠道，不写入仓库或前端。提示词限定为从给定英语正文中提取与目标层级相符的 1–3 个词汇、语法或句型知识点，并返回可校验的结构化结果。
2. 后端只在已完成阅读且当前缓存未命中时调用。请求包含处理该任务所需的文章正文、目标层级和必要的内容版本标识；不发送学生姓名、学号、考试原始分数、聊天记录、浏览行为或可反查个人身份的标识。把文章视为不可信输入，不执行正文中的指令。对外部来源文章，先核对平台取得内容及交由第三方处理的权限。
3. 校验返回结果的类型、数量、长度和原文依据：引用的原句必须能在发送的正文中定位，解释与练习建议不能伪造原文内容。模型超时、不可用或校验失败时回退到现有本地提取，且不缓存无效输出。
4. 继续复用 `text_id + content_version + target_level + SHA-256(正文)` 缓存及按用户投递的未读消息；同一文章和层级不因不同学生重复调用模型。补充模型版本与生成来源的追踪设计，再通过 Flyway 演进数据库结构，不直接改线上表。
5. 增加服务端测试：缓存命中不调 HiAgent、请求不含个人信息、输出可追溯到原文、故障回退、并发去重和多用户消息隔离；在测试环境验证延迟、费用、内容质量与合规后再逐步开启。
